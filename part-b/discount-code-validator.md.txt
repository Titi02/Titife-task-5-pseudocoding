# Part B — Discount Code Validator

## 1. Feature Description

**Feature:** Discount Code Validator

**Purpose:** Check whether a discount code can be used before applying a discount to an order.

The validator must check that:

1. The code exists.
2. The code is active.
3. The code has not expired.
4. The order meets the minimum purchase amount.
5. The code has not reached its usage limit.

## 2. Planned Behaviour

- If all checks pass, return that the code is valid.
- If a check fails, return an appropriate error explaining why the code cannot be used.
- Do not apply the discount or change the order total in this function.


## 3. Pseudocode — My First Attempt

**Inputs:** Discount code, current date, order amount, and discount-code details.

1. RECEIVE the discount code and order details.
2. CHECK whether the discount code exists.
3. IF the code does not exist, RETURN an error and stop.
4. CHECK whether the code is active.
5. IF the code is inactive, RETURN an error and stop.
6. CHECK whether the code has expired.
7. IF the code has expired, RETURN an error and stop.
8. CHECK whether the order meets the minimum purchase amount.
9. IF the order is below the minimum, RETURN an error and stop.
10. CHECK whether the usage limit has been reached.
11. IF the usage limit has been reached, RETURN an error and stop.
12. RETURN that the discount code is valid.

**Output:** Either a valid result or an error explaining why the code cannot be used.


## 4. Manual Trace Table

| Test | Scenario | Expected Result | Reason |
|---|---|---|---|
| 1 | Code exists, active, not expired, minimum met, usage limit not reached | Valid | All checks pass |
| 2 | Code does not exist | Invalid | Code lookup fails |
| 3 | Code exists but is inactive | Invalid | Code is not active |
| 4 | Code has expired | Invalid | Expiry date has passed |
| 5 | Order amount equals the minimum purchase amount | Valid | The minimum amount is met |

### Awkward Case

**Test 5:** The order amount equals the minimum purchase amount exactly. The code should be accepted because the order meets the minimum, rather than falling below it.


## 5. Implementation Decisions

1. Validate the code's existence first, then active status, expiry, minimum order amount, and usage limit.
2. An order amount equal to the minimum purchase amount is accepted.
3. A code is expired when the current time is equal to or later than its expiry time.
4. If the expiry date is `null`, skip the expiry check.
5. A usage limit of zero or less makes the code unavailable.
6. A negative order amount is invalid.
7. Return the first validation failure and do not continue checking later rules.
8. The function must not access the database or network or change any data.

## 6. Implementation and Verification Results

**Implementation file:** `lib/validation/discount-code.ts`

**Test file:** `tests/records/discount-code.test.ts`

The implementation was reviewed against the pseudocode and the following behaviours were confirmed:

- Empty and whitespace-only codes are rejected.
- Negative, `NaN`, and infinite order amounts are rejected.
- Missing and inactive codes are rejected.
- Codes that have expired, including exactly at the expiry time, are rejected.
- An order amount equal to the minimum is accepted.
- Zero or negative usage limits are rejected.
- Codes that have reached their usage limit are rejected.
- A valid code returns `{ ok: true, code }`.
